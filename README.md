# restaurant-platf# Система управления заказами в ресторане (Backend)

Высоконагруженная микросервисная платформа для автоматизации работы и управления заказами в ресторане. 
Система спроектирована на базе микросервисной архитектуры с асинхронным взаимодействием, распределенными транзакциями, 
кэшированием, централизованной маршрутизацией и надежными интеграционными тестами.

## Стек технологий и инструменты

* **Backend:** Java 17, Spring Boot 3
* **Микросервисы:** Spring Cloud Gateway, Eureka Discovery, Spring Cloud Config Service
* **Обмен сообщениями:** Apache Kafka (паттерн Saga)
* **Базы данных и кэширование:** PostgreSQL, Redis
* **Безопасность:** Spring Security, JWT (JSON Web Tokens)
* **Тестирование:** JUnit 5, Testcontainers (PostgreSQL, Kafka)
* **DevOps:** Docker, Docker Compose

## Архитектурный обзор системы

Проект состоит из **6 инфраструктурных и бизнес-микросервисов**, координируемых через единый шлюз API Gateway:

1. **API Gateway (Spring Cloud Gateway):** Центральная точка входа. Выполняет маршрутизацию запросов, ограничение 
частоты запросов (rate limiting) и глобальную валидацию JWT. Извлекает данные пользователя и передает их дальше через 
кастомный заголовок `X-User-Id`.
2. **Eureka Server:** Сервер обнаружения (Service Discovery) и реестр всех запущенных сервисов.
3. **Config Service:** Централизованное управление конфигурациями для всех микросервисов системы.
4. **Auth Service:** Отвечает за регистрацию пользователей, аутентификацию и безопасную генерацию JWT-токенов.
5. **Order & Payment Services:** Управляют жизненным циклом заказов и проведением транзакций.
6. **Kitchen & Notification Services:** Обрабатывают этапы приготовления блюд и отправляют асинхронные уведомления.

### Ключевые архитектурные паттерны:
* **Распределенные транзакции (Saga Choreography):** Бизнес-процессы между микросервисами синхронизируются асинхронно 
    через события в Kafka:  
  `OrderCreated` (Заказ создан) ➔ `PaymentProcessed` (Оплата прошла) ➔ `KitchenOrderReady` (Блюдо готово) ➔ `Notification` (Уведомление отправлено).
* **Кэширование:** Интегрирован Redis для кэширования часто запрашиваемых позиций меню и активных заказов, что снижает нагрузку на основную базу данных.
* **Безопасность:** Хеширование паролей с помощью BCrypt. Внутренние микросервисы доверяют запросам, которые уже прошли проверку на шлюзе Gateway.

## Как запустить проект

Вся инфраструктура и сервисы могут быть быстро развернуты с помощью готового автоматического скрипта:

1. Склонируйте репозиторий https://github.com/Viikklly/restaurant-platform/tree/dev_T и перейдите в корневую директорию проекта.
2. Запустите скрипт автоматизации через PowerShell:
   ```powershell
   ./restaurant-platform/start.ps1
   ```
3. Выберите **Пункт 1** в интерактивном меню консоли, чтобы автоматически собрать проект и запустить все сервисы через Docker Compose.
